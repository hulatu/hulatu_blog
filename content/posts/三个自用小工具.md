一篇稿子写完，事情才刚开始。

它得先变成十一种形态才能被看见：公众号要全内联样式的 HTML，豆瓣要富文本，少数派要规整的 Markdown，小红书要一千字以内的重写版。发出去之后，读者点进来，屏幕有一半是广告和「关联阅读」。再然后你打开 B 站想放松一下，发现「网页全屏」那个按钮藏在控制条里 —— 得先把鼠标移进播放器、等控制条浮出来、再找那个小图标。

这三件事看起来毫无关系。但做着做着我发现，我干的是同一件事：**跟平台的默认形态较劲**。

默认形态是平台定的，它服务的是平台的目标（停留、曝光、转化），不是我的目标（发出去、读进去、看下去）。这三者不总是一致，中间那点缝，就得自己填。

于是有了三个工具。都不大，都只解决一件事，都开源。

## 一、文章分发台：一篇稿子，十一种形态

同一篇 `.md`，扔进去，左边点平台，右边拿产物。

![文章分发台主界面：左侧是 11 个平台，中间是公众号预览，顶栏显示正文 4732 字、字符占用 12481/20000](/images/tools/publish-ui.webp)

麻烦的地方在于，每个平台要的东西根本不是一个东西：

| 平台 | 怎么处理 |
| --- | --- |
| 少数派、知乎 | **直接转**：规整的 Markdown + 图片上传清单 |
| 微信公众号 | **要排版**：全内联样式的 HTML（微信不认 `<style>` 和 `class`） |
| 豆瓣、B 站专栏、头条号、百家号 | **要清洗**：标准 HTML，清洗强度依次递增 |
| 小红书、推特、即刻、微博 | **要改写**：按平台语气重写的短文案 + 配图 |

前三类是**确定性转换**：不调模型、秒出、同一份输入永远同一份输出。这类事不该花一分钱 token，也不该等。只有最后一类要动大模型。

B 站专栏、头条号、百家号这三家共用一套渲染，只按两处真实差异分叉。B 站专栏允许正文里的 `<a>`，头条和百家号会把链接清掉 —— 所以链接一律抽成文末「参考链接」纯文本。代码块三家都不保证等宽，统一提示「粘贴后要检查格式」。这两条看着琐碎，但错了页面上完全看不出来，直到你粘进编辑器才发现链接全变成死文字。

### 改写为什么是两段式

真正花时间的不是转换，是改写。

我一开始是一步到位：把全文丢给模型，让它直接产出四个平台的文案。结果很差 —— 模型只盯着开头几段，后半篇整体丢失，所谓「要点」也没有结构锚点，读起来是一堆散句。

现在拆成两段：

```
① 全文 → 按 ## 切节 → 每节 1–2 句摘要（可手改）
② 摘要 → 按平台重写 → 四个平台的成品文案
```

这样做的收益是**可验证**：

| 收益 | 具体怎么做 |
| --- | --- |
| 覆盖能查 | 要点数量 = 小节数量，漏掉一节会被校验打回，模型少给就本地补齐 |
| 空壳句不合格 | 「本节介绍了……」「综上所述」开头一律重写 |
| 结构能查 | 小红书正文里没有「· 小标题：一句话说明」这种要点行，就打回重来 |
| 只重跑需要的 | 改完摘要再生成；切换平台只跑第②段，不重复烧 token |

中间那层摘要是可以逐条手改的。这一步很关键 —— 模型理解偏了的地方，你在这一层就能拦住，不用等成品出来才发现整篇跑歪。

### 图片图注，和一个我自己埋的 bug

写长文总要配图，配图总要有说明。以前每张图都要手动在下面敲一行小字，这次索性让工具自己生成：图下方一行居中灰字，字号是正文的 0.82 倍，优先用 alt，alt 为空才退回文件名，`data:` 开头的 base64 图不生成（那是图标不是插图）。

有意思的是上线前我顺手写了个断言脚本，才发现一个更早就存在的 bug：

`markdown-it` 把图片的说明文字放在 `token.content` 里，**不在 attrs 里**，而我只读了 attrs。也就是说，在这个我自己写的工具里，**我博客里 244 张图的说明一直是空的** —— 导出成 Markdown 时统统变成了 `![](url)`，图注也无从生成。整个过程不报错，界面上也看不出来，因为「图片能显示」。

这种 bug 是最难自查的那类：功能看着正常，只有真的把产物粘到平台上才发现少了东西。

### 剩下的几件小事

- **发布台账**：复制即标记已发，11 个平台的进度一眼看到，链接可以事后补
- **草稿箱**：摘要、四平台文案、标题候选自动存盘，关掉标签页也不丢
- **合规检查**：本地词表 + 正则，不联网，正文一个字节都不出浏览器
- **配图卡片**：封面 + 每个小节一张 + 结尾，3:4 / 1:1 / 16:9 三种比例按比例重排（不是整体缩放，不然 16:9 的字会小一半）
- **标题与标签**：一次给 8 个角度，至少 3 条在 20 字内 —— 小红书标题上限就在那

### 一个刻意的边界：不做一键发布

公众号没有给个人开放发布接口，绕过去的路子都是灰的。所以这个工具只做两件事：**把产物复制到剪贴板**，和**复制完把发布页打开**。

不碰账号、不填表、不代发。多按一次「粘贴」，换的是不用把登录态交给一个网页工具 —— 这笔交易我觉得值。

它也没有服务器。Key 存在你自己浏览器的 `localStorage` 里，请求从浏览器直连服务商，没有任何中转。所以它断网也能打开（Service Worker 缓存了外壳），草稿箱照样能看。

## 二、少数派阅读增强：把屏幕还给正文

少数派的列表页把三分之二的屏幕给了轮播、侧栏和推广卡；文章页在正文之后又堆了近 2000px 的广告、打赏、评论和「关联阅读」。

这个脚本做的事很简单：把它们拿掉。

![改造后的少数派首页：列表拉宽到 1064px，单条压到 99px 高，一屏能看 9 篇](/images/tools/sspai-home.webp)

1440×900 窗口下实测：

| | 首页 | Matrix | 作者主页 |
| --- | --- | --- | --- |
| 列表宽度 | 520 → **1064px** | 741 → **1064px** | 588 → **1064px** |
| 单条高度 | 189 → **99px** | 136 → **92px** | 178 → **121px** |
| 一屏能看到 | 4 → **9 篇** | 6 → **9 篇** | 5 → **7 篇** |

一屏从 4 篇变成 9 篇，这个差别不是「好看一点」，是「愿不愿意打开」。

文章页更夸张。一篇长文原文总高 **13466px**，其中约 2400px（18%）不是正文：

| 清掉的块 | 高度 | 是什么 |
| --- | --- | --- |
| `.related__read__wrapper` | 864px | 「关联阅读」 |
| `.advertisement__box` | **398px** | 文末广告位 |
| `.comment__footer__wrapper` ×7 | 392px | 正文每个章节末尾的「发表首评 + 表情」互动条 |
| `.post__comments` | 237px | 讨论区（底部固定栏的评论按钮还能打开弹窗，入口没丢） |
| `.article__charge__card` | 222px | 「N 位派友已充电」打赏卡 |

清完是 11097px。保留的是正文、文章标签与责编信息、目录，以及底部那条「说点什么…／分享」固定栏。

![改造后的文章页：正文之后直接结束，没有广告和关联阅读](/images/tools/sspai-article.webp)

### 补上的四件事

只做减法会有点空。1.3 版补了四个原站没有、但读长文真的会用到的：

- **阅读进度条**：顶部一条 2px 红线跟着滚动走，只出现在文章页。`requestAnimationFrame` 节流，不占主线程
- **点图放大**：原站的正文图点不开，页面上压根没有图片查看器。现在点一下是全屏黑底 + **原始尺寸**（用 `data-original` 里的那张，不是正文那张 1120px 的压缩版），再点一下在「适应屏幕／原始大小」之间切换
- **代码块复制**：`<pre>` 右上角悬停浮出「复制」，复制的是纯文本，不含按钮自己那两个字
- **已读标记**：读过的文章在列表里压暗到 48%，鼠标悬停恢复

![点图放大：用的是原图，不是正文里的压缩版](/images/tools/sspai-viewer.webp)

已读记录只写在你自己浏览器的 `localStorage`（`sspai-tidy:read`），最多 400 条，不上传任何地方。整个脚本只改样式、点几下按钮、写一条本地记录 —— 不碰登录态、不读你的数据、不发任何请求。

深色主题下同样生效，颜色全部走站点自己的 CSS 变量：

![深色主题下的列表页](/images/tools/sspai-dark.webp)

## 三、网页全屏：一个键的事

「网页全屏」这个按钮，在大多数视频站上都藏在播放器右下角的控制条里。有些站干脆没有这个按钮，只有「全屏」—— 那个会真的接管整个屏幕，切换窗口就得退出。

这个脚本把它变成一个键。

| 按键 | 做什么 | 什么时候不接管 |
| --- | --- | --- |
| `Esc` | 网页全屏 / 退出 | 光标在输入框里、已经在系统全屏、页面上没有像样的视频 |
| `F2` | 画中画 / 退出 | 光标在输入框里、页面上没有像样的视频 |

两个键都是「先判断自己该不该管，再决定要不要拦」。判断结果是「不该管」时，脚本什么都不做，按键原样交给站点。

### 先找官方按钮，没有再自己动手

B 站、YouTube、斗鱼、虎牙、腾讯视频、爱奇艺，这六家都有自己的网页全屏按钮（B 站还有普通视频 / 番剧 / 直播三套播放器，选择器各不相同）。脚本优先去**点它们**。

因为那才是站点自己实现的全屏：弹幕层、控制条、弹幕输入框、播放进度都由它自己摆好，比自己拿 CSS 撑大可靠得多。

只有站点没有官方按钮时，才走 CSS 兜底。兜底其实只有四行：`<video>` 变成 `position: fixed` + `100vw × 100vh` + `object-fit: contain`，祖先链清掉 `transform`（很多站的播放器被包在 `transform` 容器里，不清掉 `fixed` 会失效），再锁住 `body` 滚动。

![兜底全屏：视频铺满视口，其余页面元素让开](/images/tools/vf-fullscreen.webp)

### 真正难的是「什么时候不管」

这类接管全局按键的脚本最容易招人烦。所以 2.1 版把大部分功夫花在「不管」上：

| 情况 | 脚本的反应 |
| --- | --- |
| 页面上没有视频 | 一个 DOM 节点都不插，样式也不插 |
| 视频太小（不到视口 15%，或任一边不足 150px） | 当作没有视频，`Esc` 不拦、按钮不浮 |
| 光标在输入框 / 富文本里 | 完全不插手：不失焦、不拦按键（写评论时按 `Esc` 想取消，就该取消） |
| 已经在系统全屏 | 交给浏览器自己退，脚本不抢 |
| 判断不该管 | 不 `preventDefault`、不 `stopPropagation`，站点照常收到 |

鼠标停在视频上，右上角会浮出两个磨砂玻璃按钮，停手 2.5 秒自动收起。按钮放在 **Shadow DOM** 里，站点再激进的 `button { ... }` 也影响不到它，反过来它也不会污染站点样式。

![按钮条：磨砂玻璃两个按钮，停手 2.5 秒自动收起](/images/tools/vf-hover.webp)

还有一个很小的决定：`z-index` 用 `2147483000` 而不是 `2147483647`。留一格给站点自己的弹层，不至于被按钮条盖住。

### 用一个演示页 + CDP 跑了 8 组断言

按键类脚本光靠「我试了没问题」是不够的，得把「不该管」的那些情况也测出来：

```
1. 没有视频的页面：Esc 不被拦、一个节点都没插        ✓
2. 有视频、无官方按钮：Esc 走 CSS 兜底，再按退出      ✓
3. 有官方按钮：Esc 点按钮，不走 CSS 兜底              ✓
4. 鼠标移到视频上：按钮条浮出、定位正确               ✓
5. 点按钮条上的「网页全屏」：进入兜底全屏             ✓
6. 输入框里按 Esc：焦点不动、不触发全屏               ✓
7. 鼠标停在按钮条上：自动收起计时被推迟               ✓
8. 页面上只有小视频：不浮按钮、Esc 也不拦             ✓
```

第 8 条是这版改出来的。早期「视频够不够大」这件事，按钮浮出、`Esc`、画中画三处各写了一套判断，于是会出现「按钮出来了、按 `Esc` 却没反应」的自相矛盾。现在只有一把尺子（`bigEnough()`），三处共用。

## 四、这三个工具的共同点

回头看，三个东西虽然差得远，做法却是同一套：

**只做一件事，但把那一件做到底。** 分发台不做发布，少数派脚本不改内容，全屏脚本不管 iframe 里的播放器。边界划清楚，反而敢在每个边界内做深。

**不联网、不碰账号、数据留在本地。** 三个都没有服务端。Key 在 `localStorage`，已读记录在 `localStorage`，视频脚本连一个请求都不发。

**参数全部摊在开头。** 三个脚本/工具都有一个 `CFG` 或者设置面板，默认值写在那，想改直接改。因为默认值永远不可能对所有人正确 —— 你的窗口大小、你的站点、你的阅读习惯都跟我不同。

**都开源，MIT。** 改坏了别找我，改好了欢迎提 PR。

## 装法

三个工具，两个是 Tampermonkey 脚本，一个是网页应用：

1. **文章分发台** → 打开 [publish.hulatu.com](https://publish.hulatu.com)，拖一篇 `.md` 进去。不用注册，不用登录，AI 改写功能可选（自己填 Key）
2. **少数派阅读增强** → 装 [Tampermonkey](https://www.tampermonkey.net/)，点 [sspai-tidy.user.js](https://cdn.jsdelivr.net/gh/hulatu/sspai-tidy@main/sspai-tidy.user.js)，打开 sspai.com
3. **网页全屏** → 同上，点 [Video-Fullscreen.user.js](https://cdn.jsdelivr.net/gh/hulatu/Video-Fullscreen@main/Video-Fullscreen.user.js)，随便打开一个视频按 `Esc`

两个脚本头里都写了 `@updateURL`，以后我推新版本，Tampermonkey 会自己提示更新，不用手动重装。

---

写这三个东西最大的收获，倒不是省了多少时间 —— 而是每次跟平台的默认形态较劲的时候，我都被迫想清楚一件事：**我到底想让这一步变成什么样**。

大部分时候答案是「少一步」。少一次鼠标移进控制条，少滚 2400px 广告，少手动敲一行图注。

工具的意义大概就是这个：把「少一步」从愿望变成默认。
