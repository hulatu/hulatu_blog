做了 3 个好用的工具，分享给大家：

我喜欢写 [博客](https://hulatu.com/) ，但是常常一篇稿子写完，事情才刚开始。

因为我在不同平台都会发布内容。所以这一篇稿子它得先变成多种形态才能被看见：公众号要全内联样式的 HTML，豆瓣要富文本，少数派要规整的 Markdown，小红书要图文模式……

内容发出去之后，读者在不同平台点进来阅读，又有一个挑战。

读者会发现有些显示页面屏幕有一半是广告和「关联阅读」，还有一些其他的干扰。比如少数派的首页，干扰太多了。

有时候你想打开 YouTube、B 站放松一下，发现「网页全屏」那个按钮藏在控制条里 —— 得先把鼠标移进播放器、等控制条浮出来、再找那个小图标，很不方便。

这三件事看起来毫无关系，但确确实实会影响我们很多使用体验。做这 3 个脚本的过程中，我发现，我干的是同一件事：**把平台的默认形态转变成更适合我个人的使用习惯**。

于是有了我自己编写了三个工具。都不大、不复杂，但能解决一些痛点、提升一些体验，这些工具都开源，供大家使用。

## 一、文章分发台：一篇稿子，多种形态

地址：[文章发布页](https://github.com/hulatu/Publishing_Platform)

同一篇 `.md`，扔进去，左边点平台，右边拿产物。

![文章分发台主界面：左侧是 11 个平台的列表，中间是公众号预览，顶栏实时显示正文字数与字符占用](https://img.hulatu.com/post/Nx2xGf.webp)

麻烦的地方在于，每个平台要的东西根本不是一个东西：

| 平台                           | 怎么处理                                                     |
| :----------------------------- | :----------------------------------------------------------- |
| 少数派、知乎                   | **直接转**：规整的 Markdown + 图片上传清单                   |
| 微信公众号                     | **要排版**：全内联样式的 HTML（微信不认 `<style>` 和 `class`） |
| 豆瓣、B 站专栏、头条号、百家号 | **要清洗**：标准 HTML，清洗强度依次递增                      |
| 小红书、推特、即刻、微博       | **要改写**：按平台语气重写的短文案 + 配图                    |

前三类是**确定性转换**：不调模型、秒出、同一份输入永远同一份输出。这类事不该花一分钱 token，也不该等。只有最后一类要动大模型。

B 站专栏、头条号、百家号这三家共用一套渲染，只按两处真实差异分叉。B 站专栏允许正文里的 `<a>`，头条和百家号会把链接清掉 —— 所以链接一律抽成文末「参考链接」纯文本。代码块三家都不保证等宽，统一提示「粘贴后要检查格式」。这两条看着琐碎，但错了页面上完全看不出来，直到你粘进编辑器才发现链接全变成死文字。

### 改写为什么是两段式

真正花时间的不是转换，是改写。

我一开始是一步到位：把全文丢给模型，让它直接产出四个平台的文案。结果很差 —— 模型只盯着开头几段，后半篇整体丢失，所谓「要点」也没有结构锚点，读起来是一堆散句。

现在拆成两段：

```
① 全文 → 按 ## 切节 → 每节 1–2 句摘要（可手改）
② 摘要 → 按平台重写 → 四个平台的成品文案
```

这样做的收益是**可验证**：

| 收益         | 具体怎么做                                                   |
| :----------- | :----------------------------------------------------------- |
| 覆盖能查     | 要点数量 = 小节数量，漏掉一节会被校验打回，模型少给就本地补齐 |
| 空壳句不合格 | 「本节介绍了……」「综上所述」开头一律重写                     |
| 结构能查     | 小红书正文里没有「· 小标题：一句话说明」这种要点行，就打回重来 |
| 只重跑需要的 | 改完摘要再生成；切换平台只跑第②段，不重复烧 token            |

中间那层摘要是可以逐条手改的。这一步很关键 —— 模型理解偏了的地方，你在这一层就能拦住，不用等成品出来才发现整篇跑歪。

### 图片图注

写长文总要配图，配图总要有说明。以前每张图都要手动在下面敲一行小字，这次索性让工具自己生成：图下方一行居中灰字，字号是正文的 0.82 倍，优先用 alt，alt 为空才退回文件名，`data:` 开头的 base64 图不生成（那是图标不是插图）。

### 剩下的几件小事

- **发布台账**：复制即标记已发，11 个平台的进度一眼看到，链接可以事后补
- **草稿箱**：摘要、四平台文案、标题候选自动存盘，关掉标签页也不丢
- **合规检查**：本地词表 + 正则，不联网，正文一个字节都不出浏览器
- **配图卡片**：封面 + 每个小节一张 + 结尾，3:4 / 1:1 / 16:9 三种比例按比例重排（不是整体缩放，不然 16:9 的字会小一半）
- **标题与标签**：一次给 8 个角度，至少 3 条在 20 字内 —— 小红书标题上限就在那

### 不做一键发布

公众号没有给个人开放发布接口，绕过去的路子都是灰色地带。所以这个工具只做两件事：**把产物复制到剪贴板**，和**复制完把发布页打开**。

不碰账号、不填表、不代发。多按一次「粘贴」，换的是不用把登录态交给一个网页工具 —— 这笔交易我觉得值。

它也没有服务器。Key 存在你自己浏览器的 `localStorage` 里，请求从浏览器直连服务商，没有任何中转。所以它断网也能打开（Service Worker 缓存了外壳），草稿箱照样能看。

## 二、少数派阅读增强：把屏幕还给正文

地址：[少数派增强脚本](https://github.com/hulatu/sspai-tidy)

少数派的列表页把三分之二的屏幕给了轮播、侧栏和推广卡；文章页在正文之后又堆了广告、打赏、评论和「关联阅读」。

我的这个脚本做的事很简单：把它们拿掉。

![改造后的少数派首页：列表拉宽到 1064px，单条压到 99px 高，一屏能看 9 篇](https://img.hulatu.com/post/flV5bI.webp)

使用脚本后，一屏从 4 篇变成 9 篇，这个差别不是「好看一点」，是「愿不愿意打开、更适合浏览」。

文章页更夸张。一篇长文原文总高 **13466px**，其中约 2400px（18%）不是正文：

| 清掉的块                       | 高度      | 是什么                                               |
| :----------------------------- | :-------- | :--------------------------------------------------- |
| `.related__read__wrapper`      | 864px     | 「关联阅读」                                         |
| `.advertisement__box`          | **398px** | 文末广告位                                           |
| `.comment__footer__wrapper` ×7 | 392px     | 正文每个章节末尾的「发表首评 + 表情」互动条          |
| `.post__comments`              | 237px     | 讨论区（底部固定栏的评论按钮还能打开弹窗，入口没丢） |
| `.article__charge__card`       | 222px     | 「N 位派友已充电」打赏卡                             |

用我的脚本清理、处理后是 11097px。保留的是正文、文章标签与责编信息、目录，以及底部那条「说点什么…／分享」固定栏。

![改造后的文章页：正文之后直接结束，没有广告、打赏和「关联阅读」](https://img.hulatu.com/post/V7NOrX.webp)

### 补上的四件事

只做减法会有点空。1.3 版补了四个原站没有、但读长文真的会用到的：

- **阅读进度条**：顶部一条 2px 红线跟着滚动走，只出现在文章页。`requestAnimationFrame` 节流，不占主线程
- **点图放大**：原站的正文图点不开，页面上压根没有图片查看器。现在点一下是全屏黑底 + **原始尺寸**（用 `data-original` 里的那张，不是正文那张 1120px 的压缩版），再点一下在「适应屏幕／原始大小」之间切换
- **代码块复制**：`<pre>` 右上角悬停浮出「复制」，复制的是纯文本，不含按钮自己那两个字
- **已读标记**：读过的文章在列表里压暗到 48%，鼠标悬停恢复

![点图放大：打开的是原图，不是正文里那张 1120px 的压缩版](https://img.hulatu.com/post/iYADjs.webp)

已读记录只写在你自己浏览器的 `localStorage`（`sspai-tidy:read`），最多 400 条，不上传任何地方。整个脚本只改样式、点几下按钮、写一条本地记录 —— 不碰登录态、不读你的数据、不发任何请求。

深色主题下同样生效，颜色全部走站点自己的 CSS 变量：

![深色主题下的列表页：颜色全部走站点自己的 CSS 变量，脚本不另配一套](https://img.hulatu.com/post/WpCpbL.webp)

## 三、网页全屏：一个键的事

地址：[网页全屏工具](https://github.com/hulatu/Video-Fullscreen)

我喜欢用电脑浏览器看 YouTube 和 bilibili 的内容，但有时候也需要在浏览器里处理别的事情，所以我想要「视频」的显示范围尽可能大、而且没有别的东西干扰。网页全屏是个很好的功能，但是并不是每个网站都适配，而且就算适配了，用起来也没那么「方便」。对于我来说，网页全屏是个高频使用的功能，所以理应像我平时使用 Mac 的快捷键那样方便。

「网页全屏」这个按钮，在大多数视频站上都藏在播放器右下角的控制条里。有些站干脆没有这个按钮，只有「全屏」—— 那个会真的接管整个屏幕，切换窗口就得退出。

我这个脚本，把「网页全屏」变成一个 `Esc` 键。

| 按键  | 做什么          | 什么时候不接管                                       |
| :---- | :-------------- | :--------------------------------------------------- |
| `Esc` | 网页全屏 / 退出 | 光标在输入框里、已经在系统全屏、页面上没有像样的视频 |
| `F2`  | 画中画 / 退出   | 光标在输入框里、页面上没有像样的视频                 |

![CSS 兜底全屏：视频铺满视口，页面其余部分让开](https://img.hulatu.com/post/4jBKT4.webp)

![按钮条：磨砂玻璃的两个按钮，鼠标停手 2.5 秒自动收起](https://img.hulatu.com/post/H2UQZm.webp)

我觉得，对于很多喜欢在浏览器上看视频网站的人，这个脚本有很大帮助，会持续提升使用体验。

## 四、这三个工具的共同点

这三个东西虽然感觉不同类别、不同风格，但其实做法和目标却很明确、很专一：

**只做一件事，但把那一件做到底。** 分发台不做发布，少数派脚本不改内容，全屏脚本不管 iframe 里的播放器。边界划清楚，反而敢在每个边界内做深。

**不联网、不碰账号、数据留在本地。** 三个都没有服务端。Key 在 `localStorage`，已读记录在 `localStorage`，视频脚本连一个请求都不发。

**参数全部摊在开头。** 三个脚本/工具都有一个 `CFG` 或者设置面板，默认值写在那，想改直接改。因为默认值永远不可能对所有人正确 —— 你的窗口大小、你的站点、你的阅读习惯都跟我不同。

**都开源，MIT。** 改坏了别找我，改好了欢迎提交分享。

## 安装方法

这三个工具，两个是 Tampermonkey 脚本，一个是网页应用：

1. **文章分发台** → 打开 [publish.hulatu.com](https://publish.hulatu.com)，拖一篇 `.md` 进去。不用注册，不用登录，AI 改写功能可选（自己填 Key）
2. **少数派阅读增强** → 装 [Tampermonkey](https://www.tampermonkey.net/)，点 [sspai-tidy.user.js](https://raw.githubusercontent.com/hulatu/sspai-tidy/main/sspai-tidy.user.js)，打开 sspai.com
3. **网页全屏** → 同上，点 [Video-Fullscreen.user.js](https://raw.githubusercontent.com/hulatu/Video-Fullscreen/main/Video-Fullscreen.user.js)，随便打开一个视频按 `Esc`

两个脚本头里都写了 `@updateURL`，以后我推新版本，Tampermonkey 会自己提示更新，不用手动重装。

写这三个东西最大的收获，倒不只是满足了自己的成就感 —— 而是让自己每天实实在在会用到的东西，更好用了。

大部分时候「少一步、清爽一些」，对于工作效率和使用体验上的提升，是很直观的。

工具的意义大概就是这个：把「少一步」从愿望变成现实、变成专属于自己的默认模式。
